# Message Board Vault

**CSC 4360 — Mobile App Development**

**Developer:** Eyobed Gebregziabher

## Project Overview

Message Board Vault is a Flutter mobile application that allows users to register, log in, and share messages on a real-time message board.

The application uses Firebase Authentication to manage user accounts and Cloud Firestore to store messages. Users can view messages from other users, but they can only edit or delete messages they created.

## Technologies Used

- Flutter and Dart
- Firebase Authentication
- Cloud Firestore
- Firebase Security Rules
- Android Studio and Android Emulator
- Git and GitHub

## Main Features

- User registration with first name, last name, email, and password
- Secure login and logout using Firebase Authentication
- Automatic navigation based on authentication status
- Firestore user profiles
- Create, read, update, and delete messages
- Real-time message updates using Firestore streams
- Edit and delete controls for the message owner
- Firestore security rules that prevent unauthorized operations
- Loading indicators, form validation, and error handling
- Duplicate message submission prevention
- Offline message caching and synchronization

## Firestore Database Structure

### Users Collection

**Collection:** `users`

**Document ID:** Firebase Authentication UID

| Field | Description |
|---|---|
| `uid` | Unique Firebase user ID |
| `firstName` | User's first name |
| `lastName` | User's last name |
| `role` | User role, currently `user` |
| `registrationDateTime` | Registration timestamp generated by Firestore |

The user profile is created during registration.

### Messages Collection

**Collection:** `messages`

| Field | Description |
|---|---|
| `text` | Message content |
| `authorUid` | UID of the message creator |
| `authorName` | Name displayed with the message |
| `createdAt` | Server timestamp when the message was created |
| `editedAt` | Server timestamp of the latest edit, or null |

Messages are displayed using a Firestore `snapshots()` stream, allowing the board to update automatically.

## Firebase Security Rules

The application uses Firestore security rules to protect user profiles and messages.

- Only authenticated users can read messages.
- Users can only create messages using their own UID.
- Users can only edit or delete their own messages.
- Users cannot change message ownership after creation.
- Users can only read their own profile documents.
- User profile updates and deletions are restricted.

The security rules are available in [`firestore.rules`](firestore.rules).

## Installation and Setup

### Requirements

- Flutter SDK
- Android Studio or another Flutter-compatible development environment
- Android emulator or physical Android device
- Firebase project configured for Android

### Running the Application

Clone the repository:

```bash
git clone https://github.com/eyobedmerhawi/Message_board_vault.git
```

Navigate into the project:

```bash
cd Message_board_vault
```

Install dependencies:

```bash
flutter pub get
```

Configure Firebase for your own Firebase project using FlutterFire CLI if necessary:

```bash
flutterfire configure --platforms=android
```

Run the application:

```bash
flutter run
```

The included Firebase configuration identifies the development Firebase project. A separate Firebase project is recommended for independent testing.

### Security Testing

Two test accounts were used to verify message ownership.

User B was able to view messages created by User A but could not access the Edit or Delete controls for those messages.

An unauthorized update was also attempted directly through the Firebase SDK. Firestore returned `permission-denied`, confirming that the security rules rejected the operation.

Additional ownership restrictions were tested using the Firebase Rules Playground.

### Offline Testing

Previously loaded messages remained visible after disconnecting the device from the internet.

A message submitted while offline was synchronized after the device reconnected.

## AI-Assisted Testing

ChatGPT was used to predict the result of an unauthorized Firestore update.

The prediction was that Firestore would reject the operation when the authenticated user's UID did not match the message owner's UID.

The prediction was verified by performing an actual Firebase SDK update attempt, which returned `permission-denied`.
